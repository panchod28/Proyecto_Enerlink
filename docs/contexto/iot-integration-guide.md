# IoT Module Frontend Integration Guide

> **For frontend developers who have never seen the backend**

This document explains what changed in the IoT module, how the backend works now, and exactly what the frontend needs to do to integrate with the new IoT device persistence system.

---

## Section 1: What Changed and Why

### Before (Old System)
The IoT module used to return **hardcoded mock data** that was the same for every user:
- Devices were not stored in a database
- Every user saw the same fake devices (like "Smart Meter 1", "Solar Panel Array")
- No ability to create, update, or delete devices
- Data came from fake/mock clients (`SmartHomeProviderClient`, `EnergyCloudProviderClient`)

### After (New System)
Now the IoT module uses a **real PostgreSQL database** with per-user device management:
- Devices are stored in the `iot_device` table in Supabase PostgreSQL
- Each device belongs to a specific user (via `userId` field)
- Users can only see and manage their own devices
- Full CRUD operations: Create, Read, Update, Delete devices
- The same endpoint URLs still work, but now return real database records

### What the Frontend Needs to Change
1. **Stop using mock data** - The backend no longer returns fake devices
2. **Pass the logged-in user's ID** to filter devices by user
3. **Set `userId` when creating devices** - Devices must belong to a user
4. **Generate a `deviceId` on the frontend** - The backend doesn't auto-generate this field
5. **Set `timestamp` on create/update** - Should be current time in milliseconds

## Section 2: IoTDeviceData Model

### Fields Reference

| Field Name | Type | Required | Description |
|------------|------|----------|-------------|
| `id` | `number` (Long) | No* | Auto-generated by database. Only present in responses, not in create requests. |
| `deviceId` | `string` | **Yes** | Unique identifier for the device (e.g., "DEV-1234567890"). Generated by frontend. |
| `deviceName` | `string` | **Yes** | Human-readable name (e.g., "My Smart Meter") |
| `deviceType` | `string` (enum) | **Yes** | Type of device. See valid values below. |
| `currentReading` | `number` (double) | **Yes** | Current sensor reading (e.g., 1234.56 kWh) |
| `unit` | `string` | **Yes** | Unit of measurement (e.g., "kWh", "W", "V") |
| `location` | `string` | No | Where the device is located (e.g., "Living Room") |
| `status` | `string` | No | Device status (e.g., "online", "offline", "ACTIVE") |
| `timestamp` | `number` (long) | **Yes** | Last update time in milliseconds since epoch (use `Date.now()`) |
| `userId` | `number` (Long) | **Yes** | ID of the user who owns this device |

*Note: `id` is only present in responses from the backend. Do NOT send it in create requests.*

## Section 3: Complete Endpoint Reference

### GET `/api/iot/devices/{deviceId}`
**Purpose:** Get a single device by its `deviceId` (string identifier)
**Path param:** `deviceId` (string) — The device's unique string ID (e.g., "DEV-123")
**Optional query param:** `provider` (string) — Ignored by backend (legacy parameter, no effect)
**Response:** Single `IoTDeviceData` object (or `null` if not found)
**Who uses it:** All roles (CONSUMER, PRODUCER, MIXED)
**Example request:**
```http
GET /api/iot/devices/DEV-1715000000000
```
**Example response:**
```json
{
  "deviceId": "DEV-1715000000000",
  "deviceName": "Living Room Smart Meter",
  "deviceType": "SMART_METER",
  "currentReading": 1234.56,
  "unit": "kWh",
  "location": "Living Room",
  "status": "online",
  "timestamp": 1715000000000,
  "userId": 1
}
```

## Section 4: How the Frontend Should Use userId

### Key Concept: Devices Are Per-User
Each device in the database has a `userId` field that links it to a specific user. This means:
- User A can only see their own devices
- User B can only see their own devices
- The backend does NOT automatically filter by user in all endpoints

### Rule 1: Always Pass the Logged-In User's ID
When fetching devices, use the endpoint that filters by user:
```javascript
// GOOD: Filters by user
const devices = await getDevicesByUser(loggedInUser.id);

// BAD: Returns ALL devices from ALL users
const devices = await getAllDevices();
```

### Rule 2: Set userId When Creating a Device
When creating a device, you MUST set the `userId` to the logged-in user's ID:
```javascript
const newDevice = {
  deviceId: "DEV-" + Date.now(),
  deviceName: "My New Device",
  deviceType: "SENSOR",
  currentReading: 0.0,
  unit: "W",
  location: "Garage",
  status: "online",
  timestamp: Date.now(),
  userId: loggedInUser.id  // <-- REQUIRED: Set to logged-in user's ID
};

await createDevice(newDevice);
```

### Rule 3: Users Should Only See Their Own Devices
Don't show devices from other users. Always use `/api/iot/devices/user/{userId}` for listing devices.

### Concrete Example: Create Device Flow
1. User clicks "Add Device" button in the UI
2. Form appears with fields: deviceName, deviceType, currentReading, unit, location, status
3. User fills in the form
4. Frontend generates `deviceId`: `"DEV-" + Date.now()`
5. Frontend sets `timestamp`: `Date.now()`
6. Frontend sets `userId`: `loggedInUser.id`
7. Frontend sends POST request to `/api/iot/devices` with the complete object
8. Backend saves to database and returns the created device (with `id` field)
9. Frontend adds the new device to the list in the UI

## Section 6: `src/api/iot.ts` — Exact Functions Needed

Create a file at `src/api/iot.ts` with these exact function signatures:

```typescript
import { IoTDeviceData, CreateDeviceRequest, UpdateDeviceRequest } from '../types/iot';

const BASE_URL = '/api/iot/devices';

// Get all devices for the logged-in user
// Calls: GET /api/iot/devices/user/{userId}
// Returns: Array of IoTDeviceData for that user
export async function getDevicesByUser(userId: number): Promise<IoTDeviceData[]> {
  const response = await fetch(`${BASE_URL}/user/${userId}`);
  if (!response.ok) throw new Error('Failed to fetch user devices');
  return response.json();
}

// Get single device by deviceId (string identifier)
// Calls: GET /api/iot/devices/{deviceId}
// Returns: Single IoTDeviceData object
export async function getDevice(deviceId: string): Promise<IoTDeviceData> {
  const response = await fetch(`${BASE_URL}/${deviceId}`);
  if (!response.ok) throw new Error('Failed to fetch device');
  return response.json();
}

// Get all devices (all users) - Use with caution
// Calls: GET /api/iot/devices
// Returns: Array of IoTDeviceData from all users
export async function getAllDevices(): Promise<IoTDeviceData[]> {
  const response = await fetch(BASE_URL);
  if (!response.ok) throw new Error('Failed to fetch all devices');
  return response.json();
}

// Get devices by location
// Calls: GET /api/iot/devices/location/{location}
// Returns: Array of IoTDeviceData matching location
export async function getDevicesByLocation(location: string): Promise<IoTDeviceData[]> {
  const response = await fetch(`${BASE_URL}/location/${encodeURIComponent(location)}`);
  if (!response.ok) throw new Error('Failed to fetch devices by location');
  return response.json();
}

// Get devices by type
// Calls: GET /api/iot/devices/type?type={deviceType}
// Returns: Array of IoTDeviceData matching type
export async function getDevicesByType(deviceType: string): Promise<IoTDeviceData[]> {
  const response = await fetch(`${BASE_URL}/type?type=${encodeURIComponent(deviceType)}`);
  if (!response.ok) throw new Error('Failed to fetch devices by type');
  return response.json();
}

// Create a new device
// Calls: POST /api/iot/devices
// Body: CreateDeviceRequest (includes userId)
// Returns: Created IoTDeviceData with id field populated
export async function createDevice(device: CreateDeviceRequest): Promise<IoTDeviceData> {
  const response = await fetch(BASE_URL, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(device)
  });
  if (!response.ok) throw new Error('Failed to create device');
  return response.json();
}

// Update an existing device (use numeric id, not deviceId!)
// Calls: PUT /api/iot/devices/{id}
// Body: UpdateDeviceRequest
// Returns: Updated IoTDeviceData
export async function updateDevice(id: number, device: UpdateDeviceRequest): Promise<IoTDeviceData> {
  const response = await fetch(`${BASE_URL}/${id}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(device)
  });
  if (!response.ok) throw new Error('Failed to update device');
  return response.json();
}

// Delete a device (use numeric id, not deviceId!)
// Calls: DELETE /api/iot/devices/{id}
// Returns: void
export async function deleteDevice(id: number): Promise<void> {
  const response = await fetch(`${BASE_URL}/${id}`, {
    method: 'DELETE'
  });
  if (!response.ok) throw new Error('Failed to delete device');
}
```

// Full device object (returned by backend)
export interface IoTDeviceData {

  status?: string;                 // Optional status (e.g., "online", "offline")

// What to send in POST request (create device)
// Note: Don't send 'id' field (auto-generated by backend)
export interface CreateDeviceRequest {

  deviceName: string;
  deviceType: DeviceType;
  currentReading: number;
  unit: string;
  location?: string;
  status?: string;
  timestamp: number;               // Set to Date.now()

  timestamp: number;               // Update to Date.now()
